# Приёмка DeskRecall

Сценарии выполняются на фактическом MacBook и мониторах пользователя. Для MVP A проверяется восстановление поддерживаемых обычных окон; для MVP B дополнительно обязательны проверки Spaces. Сначала составить список проверяемых приложений и особенностей их окон.

## Основной цикл

1. На MacBook открыть не менее пяти обычных окон в трёх приложениях и сохранить профиль A.
2. Подключить внешний монитор, распределить окна между экранами и сохранить профиль B.
3. Изменить положения окон, отключить монитор. Дождаться стабилизации. Должен примениться A.
4. Подключить монитор. Должен примениться B, сохранённый до отключения.
5. Повторить цикл 10 раз. Не должно быть неверного выбора профиля, потери профиля или конкурирующих восстановлений.

Проверять монитор, положение и размер каждого однозначно сопоставленного поддерживаемого окна. При неизменной рабочей области допуск — 4 points; ограничения приложения фиксировать отдельно. Целевое время завершения — до 5 секунд после стабилизации экранов для 20 обычных окон; измерять отдельно от времени, потраченного macOS на подключение. При необходимости корректировать цель по результатам прототипа, а не скрывать таймауты.

## Дополнительные сценарии

| Условие | Ожидаемый результат |
| --- | --- |
| Нет сохранённого профиля | Окна не перемещаются, в меню «Для этих экранов нет сохранения» |
| Повторно нажата «Сохранить» | Заменён только профиль текущей конфигурации |
| Экран меняется во время сохранения | Снимок отклонён, прежний профиль сохранён |
| Нет или отозван Accessibility | Ясное состояние доступа, восстановление остановлено |
| Закрыто сохранённое окно | Пропуск; приложение и документ не открываются |
| Несколько одинаковых заголовков | Неоднозначное совпадение пропущено, чужие окна не двигаются |
| Приложение зависло или не поддерживает resize | Ограниченный таймаут, остальные окна обработаны |
| Переподключён док с серией событий | Применяется только актуальный план после стабилизации |
| Экран отключён во время восстановления | Старый план отменён, новое состояние обработано отдельно |
| Экран слева или выше основного | Корректные отрицательные координаты |
| Другой масштаб или рабочая область | Поддерживаемые окна остаются в доступной области |
| Закрыта крышка при внешнем мониторе | Выбран профиль доступных экранов без встроенного |
| Сон и пробуждение | Восстановление только после готовности дисплеев и сеанса |
| Блокировка экрана | Нет попыток взаимодействия с закрытым сеансом |
| Отключено автоматическое восстановление | Hotplug не двигает окна, ручная команда доступна |
| Перезапуск приложения | Профили сохранены, нет циклических запросов прав |
| Повреждённый JSON или новая версия схемы | Нет падения и молчаливого уничтожения файла |
| Зеркалирование, Stage Manager, fullscreen | Поддержка определяется матрицей; иначе явный пропуск |
| Два одинаковых монитора без устойчивой идентичности | Нет угадывания только по модели или числу экранов |

## Виртуальные столы для MVP B

Создать на двух дисплеях несколько столов, распределить тестовые окна и сохранить профиль. Затем изменить порядок, переместить окна и выполнить цикл отключения и подключения. Проверить принадлежность каждого окна, относительный порядок сохранённых столов, их мониторы и корректность активного стола в пределах возможностей backend.

Повторить с автоматически переставляемыми столами и с отдельными пространствами дисплеев. Если какая-либо настройка несовместима, приложение должно определять или явно объяснять ограничение; настройка не меняется молча. Проверить потерю возможностей backend после перезапуска Dock и обновления macOS.

Лишние пользовательские столы сохраняются. Неудачная операция не должна приводить к закрытию приложений, документов или удалению столов. Если полный результат недоступен, отчёт перечисляет конкретные невосстановленные элементы; MVP B при этом не считается прошедшим приёмку.

## Автоматические проверки после появления реализации

Покрыть логику, где ошибка меняет чужое рабочее пространство: ключи конфигураций; преобразования координат; взаимно однозначное сопоставление; отмену устаревших планов; сохранность профиля при прерванной записи; неизвестные версии схемы. Для AX и Spaces нужны интеграционные и ручные проверки: поддельный backend не подтверждает работу реальной macOS.

## Приёмка сохранения всех окон версии 0.2

Открыть окна одного приложения на двух разных столах, окно другого приложения на третьем столе, свёрнутое окно, полноэкранное окно и два окна с одинаковой геометрией. На одном из столов нажать «Проверить охват окон…», затем «Сохранить». Сверить количество и состояния в отчёте с подготовленными окнами. Переключиться на другой стол и повторить: переключение само по себе не должно уменьшать число доступных окон. Проверить скрытое приложение и приложение строки меню с настоящим окном.

Проверка и сохранение не должны переключать Spaces или раскрывать окна. Если приложение не отдаёт одно из окон, это должно быть видно как ошибка или ограничение; нельзя утверждать полный охват только по отсутствию фильтра видимости. Закрытое окно и неподдерживаемая геометрия не должны молча обрезать прежнее сохранение.

Сверить событие inventoryChecked и coverage в журнале с отчётом. Старый профиль схемы 1 должен читаться; новое сохранение схемы 2 должно иметь captureScope allAccessibleWindows и резерв старого файла. Отдельно проверить восстановление обычного окна на неактивном столе без активации и без переноса окна на активный стол.

## Приёмка системного сбора версии 0.3

Проверить без Accessibility сохранение окон на всех столах. Для каждого системного окна пользовательского приложения на Space в профиле схемы 3 должны быть systemIdentity с тем же windowID и сохранённые spaces. Сравнивать по ID, а не только геометрии. Отдельно проверить Chrome, Terminal, Calendar и Activity Monitor. Совпадающая геометрия не должна объединять окна или приводить к назначению неправильного AX объекта.

Проверить повторное чтение файла, резерв предыдущего профиля, схемы 1 и 2, другой PID, другой запуск процесса и другой boot session. Отсутствие Accessibility не должно блокировать сохранение, отсутствие AX у окна не должно исключать его из снимка. При недоступном чтении Spaces нельзя показывать подтверждённый полный охват.

## Приёмка восстановления версии 0.4

Перед тестом сохранить текущую раскладку в отдельную папку Recovery. На обычных окнах Chrome, Терминала, Календаря и Мониторинга системы изменить геометрию и принадлежность столу. Восстановить весь тестовый снимок штатным DesktopRestorer. Независимо прочитать WindowServer и сравнить по системной идентичности все окна: наличие, геометрию с допуском 4 points, точное множество целевых столов. Проверка должна отличать уже правильно расположенное окно от фактически изменённого и восстановленного.

При любом сбое вернуть исходную раскладку из Recovery и записать результаты возврата. Закрытое окно не создавать заново и не подменять другим. Неподдерживаемое изменение не считать успешным по одному лишь факту отправки запроса.

Для физического hotplug сохранить полные актуальные профили обеих конфигураций. Отключить монитор, дождаться стабилизации, проверить автоматический выбор профиля и каждое сохранённое окно; подключить снова и повторить. Модульный тест с изменёнными Space ID и переносом окна между уже подключёнными дисплеями не заменяет аппаратный цикл.


## Между загрузками macOS (0.5.0)

- Чтение старого профиля без перезаписи; резерв всех файлов Profiles и отдельный снимок текущих окон в Recovery.
- Смена boot UUID, PID, времени запуска и window ID: сопоставление по устойчивым признакам либо явному резервному правилу единственного/доминирующего окна.
- Сопоставимые окна одного приложения, совпадающие вспомогательные окна, смешанные и равные по весам группы столов не выбираются произвольно.
- Стол с распознанным содержимым на другом экране перемещается целиком; объединённые группы восстанавливаются по отдельным окнам.
- Проверка WindowServer после применения: геометрия и точное множество столов каждого сопоставленного окна. Число пропусков сохраняется, частичный успех не объявляется полным.
- Дополнительные столы не удаляются; сохранённые занимают требуемые позиции.
- Диагностический запуск `--verify-saved-restoration` пишет отдельный отчёт `Recovery/latest-reboot-test.json` и проверяет побайтное сохранение всех исходных файлов профилей.
