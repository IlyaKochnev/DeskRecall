# Архитектура DeskRecall

Нативное приложение Swift с AppKit для строки меню. Логика выбора профиля и сопоставления окон отделена от системных API, чтобы нестабильная интеграция Spaces не влияла на хранение и восстановление геометрии.

## Компоненты

| Компонент | Ответственность |
| --- | --- |
| MenuBarController | NSStatusItem, команды и краткое состояние |
| PermissionService | Проверка доверия Accessibility и объяснение доступа |
| DisplayService | Снимок экранов, идентификаторы, размеры, масштаб, зеркалирование и события |
| WindowService | Чтение поддерживаемых AX окон, проверка изменяемости и применение геометрии |
| SpacesProvider | Возможности backend, снимок столов, сопоставление и доступные операции |
| SnapshotService | Согласованный снимок с перечнем пропущенных элементов |
| ProfileStore | Codable JSON, версия схемы, атомарная запись, резерв, миграции |
| WindowMatcher | Взаимно однозначное сопоставление сохранённых и текущих окон |
| RestoreCoordinator | Стабилизация, отмена, планирование, применение и проверка результата |
| RestoreReport | Успехи, пропуски и причины без ложного сообщения «всё восстановлено» |

Интерфейс и чтение NSScreen выполняются на главном акторе. Потенциально медленные AX обращения — на выделенном последовательном исполнителе с ограничением времени. В одном процессе работает только одна операция восстановления. Файловое хранение сериализовано.

## Профиль и конфигурация экранов

`Profile` содержит `schemaVersion`, UUID профиля, дату ручного сохранения, ключ конфигурации, снимок дисплеев, окон, необязательный снимок Spaces и измеренные возможности backend.

`DisplaySnapshot` содержит UUID экрана, аппаратные признаки при доступности, встроенный или внешний тип, bounds, visibleFrame в points, scale, поворот, основной экран и принадлежность к группе зеркалирования. Числовой CGDirectDisplayID — только идентификатор текущего сеанса. UUID не считать безусловно стабильным через любой адаптер: поведение проверить на оборудовании пользователя.

Ключ выбора профиля строится из отсортированного набора устойчивых идентичностей активных экранов, признака доступности встроенного экрана и режима зеркалирования. Порядок возвращённых NSScreen не влияет на ключ. Геометрия расположения экранов и масштаб сохраняются внутри профиля, но по умолчанию не входят в основной ключ: macOS может временно изменить их при подключении. После события требуется стабильность и ключа, и геометрии. Разные раскладки одного набора дисплеев в MVP используют один профиль; именованные варианты добавляются позже.

При смене адаптера и неизвестном UUID не подбирать профиль по одному лишь количеству мониторов. При неоднозначных одинаковых дисплеях сообщить о невозможности точного сопоставления. Для clamshell ориентироваться на доступность встроенного дисплея; отдельное считывание датчика крышки для MVP не требуется.

## Снимок окна

`WindowSnapshot`: bundle identifier приложения, доступный AX identifier или document identifier, role и subrole, необязательный заголовок, идентификатор монитора, абсолютный frame в согласованной системе координат, нормализованный frame относительно рабочей области, состояние и необязательная ссылка на логический стол.

PID, AX объект и CGWindowID допустимы как краткоживущие подсказки текущего сеанса. Они не являются постоянной идентичностью окна. AX не гарантирует универсальный стабильный идентификатор; доступность document identifier и заголовков зависит от приложения. Полный путь документа и заголовки могут содержать личные данные: хранить лишь при необходимости сопоставления, локально; в обычные логи не выводить.

## Сопоставление окон

1. Ограничить кандидатов bundle identifier и типом окна.
2. Использовать валидную идентичность текущего сеанса, если приложение и объект по-прежнему совпадают.
3. Предпочесть устойчивый identifier документа или AX identifier, если они доступны и уникальны.
4. Далее оценить заголовок, тип, прежнюю геометрию и другие доступные признаки. Геометрия после hotplug — слабая подсказка, а не решающий признак.
5. Обеспечить взаимно однозначное назначение. При равных кандидатах пропустить окно; не использовать индекс окна как гарантию совпадения.

MVP ориентирован на уже открытые окна. После перезапуска приложения совпадение возможно лишь при достаточных признаках; восстановление сессии приложений не обещается.

## Координаты

Внутри ядра использовать единую глобальную систему в points с началом сверху слева и явным преобразованием на границе AppKit и Accessibility. AppKit, AX и пиксельные размеры дисплеев не смешивать. Учитывать экраны слева и выше основного, Retina и изменение основного экрана.

Для прежней рабочей области сохранять размер и положение; при изменённой области использовать нормализованный frame и ограничить его текущим visibleFrame. Сначала определить допустимый размер, затем положение; порядок фактических AX записей подтвердить прототипом и при необходимости выполнить ограниченный второй проход. Проверять результат чтением: приложение может ограничить размер. Допуск для обычных окон при неизменной геометрии — 4 points; ограничения приложения показываются отдельно.

## Автоматическое восстановление

Состояния: ожидание → стабилизация → поиск профиля → сопоставление → применение → проверка → отчёт.

На каждом событии дисплеев увеличивать номер поколения и отменять устаревший план. Начальная гипотеза стабилизации: отсутствие новых событий 1,5 секунды и два одинаковых снимка с интервалом 0,5 секунды. Максимальное ожидание — 15 секунд; при нестабильности завершать попытку с доступным ручным повтором. Значения уточнить по измерениям док-станции.

Непосредственно перед применением повторно проверить поколение, идентичности экранов и доступ. Если профиль отсутствует — завершить без изменений. Блокировка экрана откладывает восстановление до готового пользовательского сеанса. Потеря разрешений останавливает операцию. Недоступное приложение получает ограниченные повторы, а не бесконечный цикл.

Собственные перемещения окон не инициируют новую операцию. Повторное событие с неизменной топологией не должно возвращать окна к профилю после ручной перестановки пользователем. Пробуждение — отдельный повод перепроверить состояние, но не циклически навязывать раскладку.

Сохранение и восстановление не выполняются одновременно. Если конфигурация меняется во время снимка, сохранение отклоняется с сообщением «Экраны ещё подключаются». Хороший профиль не заменяется пустым или неполным без явного решения пользователя.

## Модель Spaces

`SpaceSnapshot`: собственная логическая ссылка в профиле, привязка к идентичности монитора, относительный порядок, тип, активность и системные подсказки backend. Связь окна — с логической ссылкой. Текущие номера и ID столов не переносить напрямую между сеансами.

`SpacesProvider` сообщает раздельно `canEnumerate`, `canReadMembership`, `canMoveWindows`, `canCreate`, `canReorder`, `canMoveBetweenDisplays`. Отсутствующая возможность даёт явный частичный результат. `UnsupportedSpacesProvider` не изображает успешное восстановление.

Сначала сопоставить существующие столы, затем создать недостающие при подтверждённой возможности, восстановить относительный порядок и привязку к дисплеям, перенести окна, восстановить геометрию. Лишние столы не удалять. Если backend требует переключений, это видимое ограничение режима, которое проверяется отдельно. Настройку автоматической перестановки Spaces учитывать как потенциальный источник конфликта.

## Хранение и поставка

Будущие пользовательские профили: `~/Library/Application Support/DeskRecall/Profiles/`. Это путь приложения после реализации, каталог подготовки там ничего не создаёт. Запись через временный файл и атомарную замену; сохранить предыдущую рабочую версию. Неизвестную более новую схему не перезаписывать. Повреждённый профиль изолировать и предложить повторное сохранение.

Первый пакет — обычный `.app` с LSUIElement. Требуется проверка Accessibility. Запись экрана и Apple Events не запрашивать заранее; добавлять только при доказанной необходимости выбранного backend. App Sandbox и Mac App Store оценивать отдельно после решения о Spaces. Root и системные дополнения не являются требованиями базового режима.
